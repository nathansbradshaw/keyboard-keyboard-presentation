層ごとに証拠を残す Sensor → state → queue → bytes → sound

Instrument every boundary, including queue overflow and missed deadlines.

The project already provides RTT logging, a DIAG_LOGGING switch, probe-rs and GDB configuration, three LEDs, an SSD1306 OLED, and a clean MIDI boundary that can be inspected with a monitor. Use them as a layered diagnostic path. If the raw ADC does not move, inspect mechanics, power, mux addressing, and the analog route. If delta moves but no event appears, inspect thresholds and state. If an event appears but no bytes leave, inspect the queue and UART. If bytes are correct but no sound exists, the fault is downstream. One important improvement for a production build is to count queue-full errors and deadline overruns instead of dropping them silently. Design test points, debug headers, and status outputs into revision A; software cannot observe a signal the PCB never exposes. Closing thought: the firmware is not glue after the hardware. It is the part of the instrument that decides what motion means.

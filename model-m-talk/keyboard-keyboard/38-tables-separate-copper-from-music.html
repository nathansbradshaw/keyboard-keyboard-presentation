constants.rs contains three useful boundaries. SWITCH_MAP describes physical truth: which mux and channel feed each logical switch index. SWITCH_TO_NOTE describes the Wicki-Hayden musical layout. process_events then applies policy: the first seventy switches are melody, later keys select voices and settings, and the final twenty route General MIDI drum notes to the drum channel. The snippets are condensed examples rather than contiguous source. This data-driven split is what makes the firmware reusable. A PCB revision changes physical mapping. A new isomorphic layout changes note mapping. USB MIDI or BLE MIDI changes transport. None of those should require rewriting the per-key state machine. On your keyboard, generate these tables from one source of truth if possible, and test that every physical switch maps to exactly one intended function. Transition: assemble those boundaries into the smallest build plan that produces sound early.

When step 4 fails, steps 1–3 are still known good.

This is the recommended implementation order for someone building a musical keyboard. First prove the output path with a hard-coded middle C and inspect it in a MIDI monitor. Second read only one physical key and record its raw values at rest, during slow travel, during hard travel, and on release. Use those measurements to choose filter size and thresholds. Third make the key produce exactly one NoteOn and one NoteOff, including ugly half presses and repeated taps. Add velocity only after the event trace is reliable. Fourth scale the scan topology, mapping tables, and queue, then test worst-case chords and controls. A conventional digital matrix skips ADC calibration and usually uses fixed velocity. Hall effect keeps the two-distance model. DIN, USB, and BLE are interchangeable only after the semantic event boundary. The debugging advantage of this order is enormous: every stage preserves a known sound-producing checkpoint. Transition: make the final system capable of telling you which layer is lying.

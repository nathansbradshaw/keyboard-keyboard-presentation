One millisecond. One hundred keys.

for ch in 0..MUX_CHANNELS {
    set_mux_channel(ch, s0, s1, s2);
    delay(480 * 10); // analog settling
    let readings = read_all_adcs(adc, adc_pins);
    for (mux, &val) in readings.iter().enumerate() {
        mux_raw[mux][ch] = val;
    }
    for decoder_idx in 0..4u8 {
        set_decoder(decoder_idx, enb_a, enb_b, enb_c);
        delay(480 * 5);
        mux_raw[9 + decoder_idx as usize][ch] =
            read_shared_adc(decoder_idx);
    }
}

This is the actual structure of timer_handler with concrete pin types and error plumbing compressed. TIM2 runs every millisecond. For each of eight mux channel addresses, firmware broadcasts three address bits to every mux, waits for the analog signal to settle, reads nine dedicated ADC inputs, then selects and reads four additional muxes through the decoder. Thirteen times eight gives 104 physical slots; SWITCH_MAP chooses the hundred populated Hall sensors. This is the key scaling trick for a custom keyboard: GPIO sets an address, ADC pins read groups in parallel, and a table describes which slots actually exist. Measure settling time on your own mux, sensor, source impedance, and PCB before copying these delays. Transition: a fast loop is useful only if slower work cannot steal its deadline.

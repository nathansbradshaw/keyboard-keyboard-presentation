The thesis

Why software engineers should care

The hard part was not sending MIDI. It was deciding when noisy human motion meant “play a note.”

MESSY WORLD

Motion

Hands, magnets, tolerances, drift and mechanical travel

→
SOFTWARE MODEL

Intent

Sampling, calibration, filtering, thresholds and state

→
STABLE CONTRACT

MIDI

Notes, velocity, controls and pitch bend

That translation problem is software engineering—just with magnets.

This is the promise for the talk. Do not enumerate generic lessons. State the actual problem: turn uncertain physical motion into a stable software contract. The rest of the talk follows the middle box—sampling, calibration, filtering, thresholds, state, and scheduling—before arriving at MIDI. Transition: if MIDI keyboards are solved, why build this one?

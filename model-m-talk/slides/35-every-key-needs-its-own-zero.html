for ch in 0..MUX_CHANNELS {
    set_mux_channel(ch, &mut s0, &mut s1, &mut s2);

        let readings = read_all_adcs(&mut adc, &mut adc_pins);
        for mux in 0..NUM_ADC_PINS {

for (switch_idx, &(mux, ch)) in SWITCH_MAP.iter().enumerate() {
    let avg = slot_sum[mux as usize][ch as usize]
        .checked_div(slot_count[mux as usize][ch as usize])
        .unwrap_or(0) as u16;
    baselines[switch_idx] = avg;
    filters[switch_idx].prime(avg);
}
CALIBRATION_SAMPLES = 64100 baselines
WHY PER KEY? Real hardware is uneven.
64samples at rest

baseline → filter prime

Boot with every key released.

The keyboard does not assume all Hall sensors share one zero. At boot it averages 64 readings for every populated mux slot, then stores one baseline and primes one filter per switch. That absorbs magnet height, sensor offset, and assembly tolerance. The firmware can track small drift later, but only while a key is idle and inside the release band. The practical instruction is simple: keep every key released during calibration. Transition: each new reading now goes through a very small rolling filter.

The 1 ms hot path scans the board

for ch in 0..MUX_CHANNELS {
    set_mux_channel(ch, s0, s1, s2);
    delay(480 * 10); // analog settling
    let readings = read_all_adcs(adc, adc_pins);
    for (mux, &val) in readings.iter().enumerate() {
        mux_raw[mux][ch] = val;
    }
    for decoder_idx in 0..4u8 {
        set_decoder(decoder_idx, enb_a, enb_b, enb_c);
        delay(480 * 5);
        mux_raw[9 + decoder_idx as usize][ch] =
            read_shared_adc(decoder_idx);
    }
}

Then: filter 100 keys → update states → enqueue events.

This is the actual structure of timer_handler with long concrete types and error plumbing compressed. TIM2 runs at priority 15 every millisecond. For each of eight mux channels, firmware broadcasts the address, waits for analog settling, reads nine ADC pins, then selects and reads the four decoded muxes. That is 104 sensor slots per frame before filtering one hundred mapped keys, updating state machines, scanning controls on their slower schedules and enqueueing events. Transition: the scan is high priority, but serial output is deliberately not.

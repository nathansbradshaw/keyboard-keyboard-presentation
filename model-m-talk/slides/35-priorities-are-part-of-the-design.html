SCHEDULING POLICY Input wins.
P15 scan must run P8 audio must flow P2 MIDI may wait P1 OLED may be stale

Real-time means predictable.

The scheduling policy is visible in the actual RTIC attributes. The one-kilohertz scan has priority 15. Audio DMA is 8. MIDI routing and its blocking UART writes are 2. OLED drawing is 1, because stale UI is safer than stale input. RTIC also makes shared and local ownership explicit. The takeaway is not that every task must be fast; it is that the work with a deadline must be protected from work that can wait. Transition: before a sensor value can mean movement, each key needs a rest value.
